The task and the data

Structural break

A point where the process that generates a series changes: its level, its noise, its rhythm or its memory is different afterwards.

In my project The whole competition: for each series, decide whether a break happened at the marked point.

Time series

A list of values recorded in order over time.

In my project 24,000 training series and 4,000 test series, each 256 to 1,024 points long.

Marked point / period

The position being tested. Values before it are period 0, values after it are period 1.

In my project The point always sits between 30% and 70% of the way through the series.

Label

The known right answer for a training example.

In my project 1 = break, 0 = no break. About half of the training series are breaks.

Training set / test set

Training examples have labels and are used to learn. Test examples have no labels and are only scored.

In my project Training: 24,000 series. Test: 4,000 series scored on Kaggle.

Parquet / CSV

Stands for Parquet: a column file format · CSV: Comma-Separated Values

File formats for tables. Parquet is compressed and fast; CSV is plain text.

In my project The series come as .parquet; labels and the submission are .csv.

Kaggle

A website that hosts data-science competitions and runs notebooks on its own machines.

In my project Where try4's inference notebook ran under the 2-core, 30-minute limit.

Public / private leaderboard

Stands for LB = leaderboard

Public: a score on part of the test data, shown during the competition. Private: the final score on the rest, revealed at the end.

In my project try4 public 0.87583. The final ranking uses the private score.

Measuring how good a model is

AUC

Stands for Area Under the (ROC) Curve

The chance that a random break series gets a higher score than a random no-break series. 0.5 = coin flip, 1.0 = perfect. It only cares about the order of scores, not their exact values.

In my project The competition metric. try4: 0.8724 held-out, 0.87583 public.

ROC curve

Stands for Receiver Operating Characteristic

A plot of true-positive rate against false-positive rate as the decision threshold moves. AUC is the area under it.

In my project Behind the AUC numbers.

TPR / FPR

Stands for True-Positive Rate / False-Positive Rate

TPR: share of real breaks flagged. FPR: share of no-breaks wrongly flagged.

In my project Points on the ROC curve.

Log loss

Stands for logarithmic loss (binary cross-entropy)

Penalty for confident wrong probabilities. The trees minimise it while training.

In my project The training objective of all three try4 models.

Probability / logit / log-odds

Stands for logit = log of the odds

Log-odds = log(p / (1 − p)). Trees add up scores in log-odds; the logistic (sigmoid) function turns that back into a probability.

In my project The worked example on slide 23 adds contributions in log-odds: 8.16 → 99.97%.

SD

Stands for Standard Deviation

How spread out the values are around their average.

In my project ‘Visible’ breaks on the error slide move the average or spread by more than 0.15 SD.

Decile

One tenth of a sorted list.

In my project Confidence slide: break rate in each tenth of try4's ranking.

Standard error (Hanley–McNeil)

How much a score would wobble with a different sample. Hanley–McNeil is a formula for the standard error of an AUC.

In my project A 4,000-series AUC wobbles by about ±0.005.

Testing honestly (validation)

Validation / held-out data

Data kept away from training and used only to measure the model, so the score reflects unseen data.

In my project Every reported local score is on held-out series.

Cross-validation

Stands for CV

Split the data into k groups; train on k−1, test on the one left out; repeat so every group is tested once.

In my project 5 rounds (folds). Each of the 24,000 series is held out exactly once.

Fold / round

One of the groups in cross-validation, or one train-and-test cycle.

In my project try4 uses the seed-7 folds stored as law_outer7/fold0–4.

Whole-series validation

Hold out complete series, never pieces of one, so no point of a test series is ever trained on.

In my project How try4 is tested; it matches the real test of 4,000 brand-new series.

OOF

Stands for Out-Of-Fold

Predictions made for each training example by the model that did not see it. Pooled together, they give an honest overall score.

In my project try4 OOF AUC 0.8724, rebuilt from the saved models as 0.87234.

Leakage

When information from the answers sneaks into training or feature choice, making the local score too optimistic.

In my project Caught one: picking columns with all labels gave 0.8774; doing it per round gave 0.873.

Training-only preprocessing

Anything learned from data (feature selection, priors, scaling) is fitted on the training part of each fold only.

In my project Top-100 picking, the 36 noise priors and all 3 models are fitted per round on training series only.

Early stopping

Stopping training when the validation score stops improving. Uses held-out data, so it can leak.

In my project Not used: try4 trains a fixed number of trees (720, 1,300 and 1,100).

Seed

Stands for random seed

A number that fixes random choices so a run can be repeated exactly.

In my project Folds use seed 7; the second LightGBM uses seed 29.

Overfitting

Learning the noise in the training data instead of the real pattern, so it does worse on new data.

In my project Limited with leaf caps, minimum leaf sizes, subsampling and L2 penalties.

Tree models and boosting

Decision tree

A flowchart of yes/no questions about the features (‘is X at most 3.1?’) that ends in a leaf with a score.

In my project Slide on the first real tree: its first question is any_far_strong ≤ 3.1.

Split / node / leaf

Split: one yes/no question. Node: where a split happens. Leaf: an end point that adds a score.

In my project try4's LightGBM trees have up to 27 leaves.

Gain

Stands for split gain

How much a split reduces the training loss. Summed over the model, it shows which features matter most.

In my project Used to rank columns and pick the top 100 per round. Top feature: 17.9% of the gain.

Gradient boosting

Stands for GBDT = Gradient-Boosted Decision Trees

Build a model as a sum of many small trees. Each new tree is fitted to the current errors (the gradients of the loss), so it fixes what the model still gets wrong.

In my project All three try4 models are gradient-boosted trees.

Gradient / Hessian

Gradient: the direction and size of the error for each example (prediction − label). Hessian: the curvature, p × (1 − p).

In my project Used by XGBoost to score splits and set leaf values (a Newton step).

Learning rate

Stands for shrinkage, eta

How much each new tree is allowed to change the prediction. Small = many careful steps.

In my project 0.025 / 0.015 for the LightGBMs, 0.02 for XGBoost.

XGBoost

Stands for eXtreme Gradient Boosting

A popular gradient-boosting library. Grows trees level by level to a fixed depth and uses the gradient and curvature to score splits, with L2 (lambda) and gamma penalties.

In my project One of try4's 3 models: depth 6, 1,100 trees, 80% of rows and 60% of columns per tree.

LightGBM

Stands for Light Gradient Boosting Machine (Microsoft)

A fast gradient-boosting library. Buckets each feature into a histogram and grows trees leaf-wise: it always splits the leaf with the biggest gain.

In my project Two of try4's 3 models, with different seeds and settings.

CatBoost

Stands for Categorical Boosting (Yandex)

A gradient-boosting library with symmetric (oblivious) trees, ordered boosting, and built-in handling of categorical inputs.

In my project Used in some of try3's models, not in try4.

Level-wise vs leaf-wise growth

Level-wise: split every node on a level before going deeper (XGBoost). Leaf-wise: always split the single best leaf (LightGBM).

In my project Explained in the video.

Histogram binning

Grouping a feature's values into a fixed number of buckets so splits are found by scanning bins instead of sorting values.

In my project LightGBM, up to 127 bins in try4.

Symmetric / oblivious tree

A tree where every node on the same level asks the same question.

In my project CatBoost.

Ordered boosting

Each example's error is computed by a model that only saw earlier examples in a random order, so no example grades its own homework.

In my project CatBoost.

L2 regularisation (lambda) / gamma

Stands for L2 = squared-size penalty

Lambda keeps leaf values small; gamma is the minimum gain a split must reach to be kept.

In my project XGBoost: reg_lambda 6.

Subsampling

Stands for row and column sampling, bagging

Each tree sees a random share of the rows and/or columns, which reduces overfitting.

In my project XGBoost: 80% rows, 60% columns; LightGBM seed-2: 50% of columns.

Newton step

An update that uses both the slope (gradient) and the curvature (Hessian) of the loss. Optimal leaf value = −G / (H + λ).

In my project XGBoost's split formula.

Neural networks and ensembles (try3)

Ensemble

Several models combined so their different mistakes cancel out.

In my project try3: 51 models. try4: 3.

Blend / rank averaging

Combine models by turning each model's predictions into ranks and averaging the ranks. Works well for AUC because only order matters.

In my project try4's final score: average of the 3 models' ranks.

Stacking / heads

A second-level model that takes other models' outputs as inputs and adjusts the final answer.

In my project try3's weight heads and local-rank correction edit the blended logit.

MLP

Stands for Multi-Layer Perceptron

A basic neural network: layers of weighted sums with non-linear functions in between.

In my project In try3, on about 2,171 scaled columns, trained with noise added.

CNN

Stands for Convolutional Neural Network

A neural network that slides small learned filters along the data. A 1D CNN reads a series directly and learns its own features.

In my project In try3, reading the raw series.

Data augmentation

Making extra training examples by changing existing ones (adding noise, cropping).

In my project try3's specialist trains on 2 zoomed-in crops of every series as well.

Crop / view

A cut-out or transformed version of a series around the marked point.

In my project try3 uses 8 views; the specialist uses crop views c1 and c2.

TTA

Stands for Test-Time Augmentation

Scoring a test example on several augmented versions and averaging the results.

In my project The specialist averages original (×2) and crop (×0.125 each) predictions.

Synthetic data

Made-up examples generated by a program.

In my project Only in try3's MLP correction, built from training no-break series.

MECH3C12V (the specialist)

Stands for MECH = mechanism model · 3 = version 3, with all 5 jump-law tables · C12 = crop views 1 and 2 · V = volatility law

One XGBoost on the ‘how was it produced’ measurements, all jump laws, the volatility law and the noise priors, trained with 2 crop views.

In my project Alone it scores 0.8748 (3 seeds averaged), 99.5% of try3's 51-model 0.8791.

The measurements (features)

Feature

Stands for column, measurement

One number computed from a series that describes it, such as ‘how much did the spread change?’.

In my project try4 picks 100 of 3,589 candidates per round, plus 36 noise-prior columns.

Feature table / family

A group of related features computed by one script.

In my project 35 tables in try4, for example volatility_law, memory_law1, boundary_law_state.

Feature selection

Keeping only the most useful features.

In my project Per round: rank by LightGBM gain on training rows, keep the top 100.

Bayes factor

How many times more likely the data is under one explanation than another. Its log is positive when the first explanation fits better.

In my project Most of try4's top features are log Bayes factors: ‘something changed at the point’ against ‘one process throughout’.

Prior / integrating out

Stands for marginal likelihood

A prior is what you assume before seeing the data. Integrating out means averaging over unknown settings (like the mean and scale) instead of fitting them, which is more stable on short series.

In my project How native_free_scale is computed.

Noise law

The shape of the random noise in a series: Gaussian (bell curve), heavy-tailed, skewed, spiky and so on.

In my project Each side of the point is scored against a bank of noise shapes.

Noise-law prior (law__ columns)

Stands for law_outer7 = priors fitted inside the seed-7 outer folds

Columns that say how often series with this kind of noise turned out to be breaks. Learned from labels, so fitted inside each round on training series only.

In my project 36 columns, always kept. Together about 10% of the model's decisions; law__v0 is in the top 8.

native_free_scale

Stands for noise volume test

Log Bayes factor for ‘each side has its own noise volume’ against one shared noise law.

In my project try4's top feature: 17.9% of the gain, AUC 0.82 alone.

restart_new_process

Stands for restart test

Models a slowly drifting hidden level plus noise, and asks whether that hidden process restarts with new settings at the point.

In my project Second most important feature.

Latent level

Stands for latent = hidden

An underlying level that can't be seen directly, only through noisy values.

In my project latent_level_pulse / latent_level_raw tables.

any_at / any_far_strong

Stands for boundary laws

any_at: evidence for any change exactly at the point. any_far_strong: how much stronger that is than at candidate points far away.

In my project any_far_strong is the first question of the first tree.

Phase law / common_phase

Fits a repeating rhythm and measures its phase (where in the cycle it is).

In my project Coin flip alone (AUC 0.50) but still useful in combination.

Jump law (jump_law_ tables)

Bayes-factor tests of whether the series' settings jumped at the point: the level, the noise volume (6 jump sizes each) or the noise shape (bell curve → heavy tails, outliers, two humps). Run on 5 differently cleaned-up versions of the series: pulse, state, nullstate, prestate, smoothvol.

In my project All 5 are in the specialist (the ‘3’ in MECH3C12V). In the worked example, ‘noise shape jumped’ (jump_law_prestate shape0) added +0.67 log-odds.

Volatility law / new_memory

Stands for volatility = how jumpy the series is

Tests whether the way jumpiness clusters and fades changed at the point.

In my project In the worked example, + 0.51 log-odds.

ARCH / GARCH

Stands for AutoRegressive Conditional Heteroskedasticity / Generalized ARCH

Models where today's noise size depends on recent noise sizes (volatility clustering).

In my project GARCH table dropped in try4 for speed.

AR / memory law

Stands for AutoRegressive

How much each value depends on the values before it (momentum). Partial autocorrelation measures that per lag.

In my project memory_law1 jump4 / independent_memory in the worked example.

Cramér–von Mises test

Stands for CvM

A statistical test of whether two sets of values come from the same distribution.

In my project grid2 r_mrng10_cvm: CvM test on a rolling 10-point range, before against after.

Mean shift / spread ratio

The simple checks: did the average or the standard deviation change?

In my project Each scores only AUC 0.62. The ‘eyeballing’ baseline.

SHAP / pred_contrib

Stands for SHapley Additive exPlanations

Splits one prediction into how much each feature pushed it up or down. LightGBM's pred_contrib computes this for trees.

In my project The waterfall on ‘One real break, explained’.

Running it (compute)

Inference

Using a trained model to score new data.

In my project Must finish in 30 minutes on 2 CPU cores with 8 GB.

CPU / GPU

Stands for Central / Graphics Processing Unit

CPU: the general processor. GPU: a chip with thousands of small cores, fast for training big models.

In my project Trained on my own PC with GPUs; inference on Kaggle CPUs only.

RAM

Stands for Random-Access Memory

Working memory.

In my project try4 peaks at 2.6 GB of the 8 GB allowed.

Wall time

Stands for wall-clock time

Real elapsed time, as opposed to the total processor time across cores.

In my project 21.8 minutes wall time for about 41 processor-minutes.

Parallel workers

Running independent steps at the same time on different cores.

In my project --workers 2 on Kaggle.

Slim steps

My faster versions of feature steps that compute only the columns the saved models read, with identical values.

In my project try4/slim*.py; switch off with KU_TRY4_NO_SLIM=1.

Notebook (.ipynb)

Stands for Interactive PYthon NoteBook

A document mixing code and outputs, run cell by cell.

In my project inference.ipynb scores raw series on Kaggle.

requirements.txt / pip

Stands for pip = Package Installer for Python

A list of exact library versions and the tool that installs them.

In my project requirements-cpu-full.txt pins numpy, pandas, LightGBM, XGBoost and the rest.

My four tries

try1

In my project 0.83313 public. Ate most of my week.

try2

In my project 0.87539 public.

try3

try4

try3 cut down: top 100 features + 36 noise priors per round, 2 LightGBM + 1 XGBoost, rank-blended.

In my project 0.87583 public, 22 minutes on 2 cores. The selected solution.
